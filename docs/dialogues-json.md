# `dialogues.json` 对话配置

`dialogues.json` 是凡人修仙传桌宠播放器的可选初始配置，放在宠物的 `pet.json` 与 `spritesheet.webp` 旁边。Codex Desktop 仍只依赖原有两项文件，因此加入该文件不会改变 Codex Pet v2 格式。

仓库内 `pets/<id>/` 会被自动识别为内置宠物，不需要再把宠物 ID 登记到前端数组、Rust 常量或 Tauri 单独资源项中。

## 仓库内新宠物约定

向仓库加入新的 `pets/<id>/` 时，维护流程默认同时补齐符合角色人设的 `dialogues.json`，不需要再单独提出对话生成需求。新文件采用 `version: 1`，默认提供 12 条 `idle`、6 条 `drag` 和 10 条 `touch`；若角色来自已有作品，应先依据可靠资料核对其经历、说话方式和性格，避免套用通用台词。

已有 `dialogues.json` 属于人工维护内容，接入流程不会自动覆盖。若明确不希望该宠物显示对话，可以保留文件并将对应事件数组设为空，或在接入时明确要求不生成该文件。

```json
{
  "version": 1,
  "idle": ["待机时显示的第一句话", "待机时显示的第二句话"],
  "drag": ["开始拖拽时显示的话"],
  "touch": ["鼠标进入或单击宠物时显示的话"]
}
```

## 字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `version` | number | 当前固定为 `1` |
| `idle` | string[] | 按随机对话间隔触发，使用独立的防连续重复循环 |
| `drag` | string[] | 每次拖拽越过移动阈值时触发一次，使用独立循环 |
| `touch` | string[] | 鼠标进入或单击时触发，使用独立循环 |

- 宠物第一次进入播放器状态时，三组内容会从该文件导入 `player-state.json`。
- 整个文件缺失时，播放器会在 `player-state.json` 中为该宠物初始化三个空数组，不显示对话。
- 文件存在但 JSON 无法解析、版本错误或字段类型错误时，播放器会明确报错，不会把错误配置当成“缺少文件”并固化为空状态。
- 文件存在时，三组可以分别配置；空数组表示该事件不显示对话。
- 初始化完成后，`player-state.json` 是唯一运行时来源；更新宠物包不会覆盖用户已经保存的内容。
- 设置页可对 `idle`、`drag`、`touch` 单独执行“恢复默认”。播放器会重新读取该宠物包的 `dialogues.json`，立即覆盖 `player-state.json` 中选中的一组，另外两组保持不变；宠物包没有该文件或该组为空时，选中的一组恢复为空，无效文件则提示错误并保留原状态。
- 老版本保存的单组对话会迁移为 `idle`，另外两组在迁移时从宠物包补齐；宠物包也没有对应内容时使用空数组。
- 浏览器预览使用 `localStorage` 执行同样的一次性导入与持久化规则。
